Backend-first claims platform for motor and property claims across six APAC markets.
Claimants report, track and answer info requests; officers pick up, assess, decide and settle;
managers see workload and liability exposure. One Angular app serves all roles.

## Backend conventions

- Layers: Controllers (thin: route, auth, DTO -> service call) -> Services (orchestrate one use case,
  own the transaction) -> Domain (all business rules) -> Repositories (specific query methods,
  AsNoTracking + projection for reads, never expose IQueryable upward).
- The Claim aggregate owns its status. Change it only through methods such as
  `claim.Assign()`, `claim.RequestInformation()`, `claim.Approve()`, `claim.Reject()`, `claim.Settle()`.
  Never set `Status` from outside the aggregate.
- Allowed transitions: Submitted -> UnderReview (assign); UnderReview <-> AwaitingInformation;
  UnderReview -> Approved | Rejected; Approved -> Settled. Anything else throws DomainException -> HTTP 409.
- Every transition appends a ClaimStatusHistory row and raises a domain event.
- Concurrency: PostgreSQL `xmin` as the row version. DbUpdateConcurrencyException -> HTTP 409.
- Money: `numeric(18,2)` + ISO currency code. Never sum amounts across currencies.
- Errors: RFC 7807 ProblemDetails via AddProblemDetails + IExceptionHandler
  (DomainException 409, NotFoundException 404, validation 400, forbidden 403).
- Validation: DataAnnotations on request DTOs; business rules in the domain.
- Auth: demo JWT from POST /api/auth/login with seeded users; roles Claimant, Officer, Manager.
  Claimants may only read their own claims — enforce in the service, not only the controller.
- Database: snake_case naming. Migrations generated by EF Core. The API runs `MigrateAsync()` at start-up
  only when `Database:MigrateOnStartup=true`. Seeding via `UseAsyncSeeding`, idempotent.
- Nullable enabled, warnings as errors, async all the way, CancellationToken on every public async method.

## Events and Kafka

- NEVER produce to Kafka from the API request path. Services add domain events to the outbox;
  the outbox row and the business change save in ONE SaveChanges transaction.
- Outbox publisher (Worker BackgroundService): every 1 s, select unsent rows ordered by occurred_at,
  `FOR UPDATE SKIP LOCKED LIMIT 100`, produce with `Acks=All`, `EnableIdempotence=true`, set sent_at.
  Back off when Kafka is unavailable.
- Topic `claims.events` (6 partitions), message key = claimId. Dead-letter topic `claims.events.dlq`.
  Auto topic creation is off; a compose init container creates topics.
- Envelope: { eventId, eventType, version, occurredAt, claimId, correlationId, payload }.
- Consumers: group `claims-worker`, manual commit AFTER the database write. Idempotent via
  `processed_events(event_id)` inserted in the same transaction as the work.
  After 3 failures, send to the DLQ with the error and commit.

## Frontend conventions

- Smart pages (features/*/pages) inject stores and handle routing; dumb components (features/*/ui,
  shared/ui) use only `input()` / `output()` and contain no services.
- `*.api.ts`: HttpClient calls only, typed with generated types from `core/api/api-types.ts`.
  Never hand-write DTO interfaces. Regenerate with `npm run gen:api`.
- `*.store.ts`: injectable store, private `signal()` state, `computed()` derived values,
  `asReadonly()` exposure, command methods. One pattern everywhere.
- `environment.ts` apiBaseUrl `/api`; dev proxy to http://localhost:5000. No hard-coded hosts.
- Functional interceptors (auth, error -> toast). Lazy routes per role with `roleGuard`.
- Tailwind utility classes; neutral palette.
